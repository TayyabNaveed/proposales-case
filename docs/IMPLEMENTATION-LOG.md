## 11 October 2026 — Evidence-based business identity

- Root cause: identity was decided twice without shared evidence. The model gave a bare verdict, and a word-matching gate (`identitySupported`) could overrule it. The gate assumed one sentence, the whole typed location, the exact name and spaces between words. Wording fixes (v3, v4) and lexical tweaks treated symptoms.
- Ruling: the model returns quoted candidates. Code verifies that the quotes exist and that they contain or resemble the typed name and location, using character bigrams and continuous normalised text, which work in any language. ## 11 October 2026 — Saved proposal requests released once settled

## 11 October 2026 — Rejected provider writes; migration ledger

- Symptom: the Avalon Innovation proposal "could not be created". Its operation was `unknown`; the payload rebuilt locally without error, and no draft existed for its operation key.
- Root cause 1: every create failure was recorded as `unknown`, including definite client errors where nothing was created, and the error was discarded. A clear rejection looked like a lost response, and nothing could be diagnosed.
- Ruling: `classifyWriteFailure` records a provider 4xx (except 408, 409 and 429) as `rejected` with a safe code. Everything else stays `unknown`, now with a code (`outcome_unknown`, `network`, …). A rejection is final: never redispatched, never searched for, and the browser copy is released so a new request is safe. Migration 010 adds the state and `error_code` (codes only, never provider bodies).
- Root cause 2: the migration runner re-ran every file. Re-running 007 after 009 narrowed the research stage rule while intro rows existed, so `db:migrate` failed (23514) before reaching 010. Ruling: a `schema_migrations` ledger applies each migration once, in a transaction. `006_app_role` stays repeatable (idempotent grants). Databases predating the ledger are bootstrapped as 001–009, with 009's intro rule as evidence; otherwise the runner stops instead of guessing.
- Evidence: 165 offline tests; DB 12/12; migrate run twice (bootstrap 9, applied 010; rerun touched only 006). One approved retry of the Avalon request (same payload and key) returned `http_400`, now recorded as rejected. The exact rejected field is unknown because bodies are discarded by design.

The Avalon recipient had only the prefilled company name. Ruling: a recipient is sent only with an email; otherwise the draft has no recipient, the read-back check expects none, and the dialog explains this. Not related to the category layout.
